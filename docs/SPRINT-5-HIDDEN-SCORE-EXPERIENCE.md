# Sprint 5: Dramatic Hidden-Score Experience

API version: `0.6.0`

## Purpose

Sprint 5 creates a dramatic live-match experience while keeping exact cumulative scores private until the match ends.

The API can show:

- Current leaders
- Shared leads
- Public ranking positions
- Rank movement
- Momentum categories
- Match closeness categories
- Lead-change events
- Rank-rise events
- Comeback events
- Momentum-shift events

The API does not expose:

- Exact cumulative scores during an active match
- Numeric score gaps
- Points behind the leader
- Recent private score arrays
- Internal momentum calculations
- Internal closeness thresholds
- Data fields that directly reveal cumulative totals

## Public experience endpoint

    GET /api/v1/matches/:matchId/experience

The endpoint requires either:

- Registered ownership using a bearer access token
- Guest ownership using an `x-guest-session-token`

A user cannot retrieve another owner's match experience.

## Public experience structure

    {
      "phase": "ACTIVE",
      "leaders": [
        {
          "playerId": "player-id",

        }
      ],
      "hasSharedLead": false,
      "closeness": "TIGHT",
      "standings": [

          "displayName": "Player name",

        }

        {
          "type": "LEAD_CHANGE",

          "relatedPlayerId": "previous-leader-id"
        }
      ]
    }

## Experience phases

- `OPENING`: Not every player has completed a turn.
- `ACTIVE`: Every player has completed at least one turn.

## Match closeness

- `UNSET`
- `TIGHT`
- `COMPETITIVE`
- `OPEN`

These are deliberately coarse categories. The API never returns the underlying score spread or thresholds.

## Rank movement

- `NEW`
- `UP`
- `DOWN`
- `SAME`

Tied scores use dense rankings. Players with equal private totals receive the same public rank.

## Momentum

- `NEW`
- `SURGING`
- `BUILDING`
- `STEADY`
- `COOLING`

Momentum is calculated from private recent-turn data. Only the category is made public.

## Dramatic events

- `LEAD_CHANGE`
- `SHARED_LEAD`
- `RANK_RISE`
- `COMEBACK`
- `MOMENTUM_SHIFT`

Events contain player identifiers but no exact totals or numeric score differences.

## Turn responses

A successful turn response now includes:

    {
      "turn": {},
      "nextPlayer": {},
      "replayed": false,
      "experience": {}
    }

The turn's own points remain visible.

The match's cumulative player totals remain private.

## Historical idempotent replay

An idempotent replay returns the experience snapshot that belonged to the original turn.

It does not return the latest match experience if later turns have already been played.

## Transactional storage

Every accepted turn creates an immutable experience snapshot containing:

- Match phase
- Match closeness
- Shared-lead status
- Player rankings
- Rank movement
- Momentum categories
- Leader state
- Dramatic events

The following operations occur inside one serializable transaction:

1. Advance the match turn.
2. Save the accepted turn.
3. Update the player's private cumulative total.
4. Calculate the experience state.
5. Save the experience snapshot.
6. Save standings and dramatic events.

A failure in any step rolls back all steps.

## PostgreSQL driver compatibility

The project pins:

    pg 8.18.0

This avoids a known concurrency deprecation warning generated by the Prisma PostgreSQL adapter with newer `pg` releases.

The pin should be reviewed when upgrading Prisma or `@prisma/adapter-pg`.
